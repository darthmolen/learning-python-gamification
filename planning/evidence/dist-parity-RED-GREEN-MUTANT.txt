WHAT IS BEING CHECKED

`pyquest/tests/compiled-entry-points.test.ts`, in the `dist` vitest project — the only
project with no `@pyquest/* -> src/` alias. For every entry point every package
publishes, it imports the bare specifier (which resolves through `exports` to `dist/`)
and the source module (by absolute path), and compares the export names.

RED — the exact 2026-09-09 failure, reproduced

A schema added to `contract/src` and never emitted, which is what happened to
`HowToSchema`. No build run: this is the developer who types `vite`.

    $ printf '\nexport const StaleProbeSchema = z.object({ probe: z.string() });\n' \
        >> packages/contract/src/endpoints.ts
    $ printf "\nexport { StaleProbeSchema } from './endpoints.ts';\n" \
        >> packages/contract/src/index.ts
    $ npx vitest run --project dist

     FAIL  |dist| compiled-entry-points.test.ts > '@pyquest/contract'
                > exports from dist everything it exports from src
     AssertionError: FAIL  @pyquest/contract
             missing from dist:  StaleProbeSchema

           dist/ does not export what src/ does, so every app resolving the package
           entry point is reading code that no longer exists.

           fix: rm pyquest/packages/*/tsconfig.tsbuildinfo && npm run build

           `tsc -b` alone will not fix this. It never stats dist/ — it trusts the
           hashes in tsconfig.tsbuildinfo, and a branch switch pushes that file's
           mtime past every source file without changing a byte of output. See
           planning/evidence/tsc-b-trusts-buildinfo-DIAGNOSIS.txt.

     Test Files  1 failed (1)
          Tests  1 failed | 5 passed (6)

developer who reaches for `npm run build --workspace @pyquest/contract` gets exit 0.

ONE THING FOUND ALONG THE WAY, FIXED, AND WORTH RECORDING

`apps/field-manual`'s build did `rmSync(outDir, { recursive: true, force: true })`,
which fails EPERM when anything holds the directory handle — and something did: a
`python -m http.server` previewing the site, whose working directory *is* `dist/`.
The build died having produced nothing, for a reason unrelated to content.

Clearing the directory's *children* needs no such handle and clears just as
thoroughly. Changed, and the preview server picked the rebuilt site up without being
restarted.

This is adjacent to the plan rather than in it. Recorded here because "the Field
Manual builds" was a success criterion and this was the only thing standing between
the repository and that sentence.
