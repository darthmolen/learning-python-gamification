-------------------------------------------------------------------------------
A TEST THAT WAS WRONG RATHER THAN THE CODE
-------------------------------------------------------------------------------

The first RED run reported five failures, not three:

  FAIL  pyquest-api has restart=no - it will not survive a reboot
  FAIL  pyquest-runner has restart=no - it will not survive a reboot
  FAIL  pyquest-web has restart=no - it will not survive a reboot
  FAIL  pyquest-runner-tests has restart=
absent - a job that restarts is a boot loop
  FAIL  pyquest-migrate has restart=
absent - a job that restarts is a boot loop

The last two are the assertion being wrong. `runner-tests` and `migrate` are
`run --rm` jobs, so no container exists -- which is a PASS, not a boot loop.

`docker inspect` on a container that does not exist prints an empty line to
STDOUT *and* exits non-zero, so

    POLICY=$(docker inspect -f '...' "$c" 2>/dev/null || echo absent)

captures "\nabsent", which matches no `case` arm. Note the wrapped output above:
the newline is visible in the RED transcript itself.

Fixed by reading, squeezing whitespace, then deciding:

    policy_of() {
      docker inspect -f '{{.HostConfig.RestartPolicy.Name}}' "$1" 2>/dev/null | tr -d '[:space:]'
    }

After the fix, against the UNCHANGED compose files:

  pyquest-api            no
  pyquest-runner         no
  pyquest-web            no
  pyquest-runner-tests   (none/missing)
  pyquest-migrate        (none/missing)

Three real failures, two correct passes. That is the honest RED.

    restart: unless-stopped

    restart: "no"

    restart: unless-stopped

$ docker compose --profile api up -d --force-recreate --no-deps api runner
 Container pyquest-api  Recreated
 Container pyquest-runner  Started

  pyquest-api      unless-stopped
  pyquest-runner   unless-stopped

`--force-recreate` is required and is not ceremony: the policy is baked into the
container's HostConfig at CREATE time, so editing the compose file and
restarting leaves the old policy behind a correct-looking file. That is exactly
why the assertion reads `docker inspect` and not `docker compose config`.
