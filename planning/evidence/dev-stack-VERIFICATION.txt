**One listening line, not three.** Before `API_HOST` was added to `apps/api/src/main.ts`
the same command printed three — 127.0.0.1, 172.31.0.1 and 192.168.4.102 — because the
listen host was hardcoded `0.0.0.0`. Correct in the container, where loopback is the
container's own and invisible from outside (§6.1); wrong on this host, where it would
put an api with no Gitea token and a throwaway database on the LAN beside the real one.

3. THE DEV API WRITES TO ITS OWN DATABASE — ASSERTED, NOT ASSUMED
---------------------------------------------------------------------------

A full bootstrap sign-in — the heaviest write path there is: it creates a player, a
credential and a token in one request.

    BEFORE  prod: api_tokens=5 credentials=1 attempts=8 journal=0 medals=26 players=2
    BEFORE   dev: api_tokens=0 credentials=0 attempts=6 journal=0 medals=27 players=2

    $ curl -X POST http://127.0.0.1:3083/api/session/bootstrap -d '{"secret":...}'
    {"token":"sCLxXJ...","expiresAt":"2026-09-10T21:32:06.677Z",
     "account":{"id":"e8f8ea68-...","handle":"devdm","displayName":"Dev DM",...}}

    AFTER   prod: api_tokens=5 credentials=1 attempts=8 journal=0 medals=26 players=2
    AFTER    dev: api_tokens=1 credentials=1 attempts=6 journal=0 medals=27 players=3

    ASSERT PASS: production is byte-identical before and after a dev sign-in
    ASSERT PASS: the dev database did change — the write landed somewhere

**Both assertions matter.** The first is the one the plan asked for. The second is the
one that keeps the first from being vacuous: a sign-in that silently failed would also
have left production untouched, and would have proved nothing.

      import.meta.env = {"BASE_URL":"/","DEV":true,"MODE":"live","PROD":false,

    :5175  npm run dev        (mode "development")
      <that line is absent entirely — no VITE_API_LIVE at all>

Both served the identical gateway source below it:

      const apiBase = () => import.meta.env["VITE_API_LIVE"] === "true" ? SAME_ORIGIN : void 0;

So plain `npm run dev` returns `undefined` and answers from fixtures, with a live api
sitting right there on 3083 and reachable. The switch is the *mode*, not the stack.

`apps/web/Dockerfile` still carries `ENV VITE_API_LIVE=true`, so the production image is
untouched by any of this — `.env.live` is only read in `--mode live`, and `vite build`
runs in mode `production`.

7. WHAT RELOADS — AND THE PLAN'S RECOMMENDATION TURNED OUT TO BE TOO BLUNT
---------------------------------------------------------------------------

The plan said "restart the process" and recommended it over a reload endpoint or a
watcher. That recommendation stands. But it is coarser than the truth, and the truth is
better news: **the api reads content two different ways.**

`apps/api/src/content.ts` returns `items`, `manifests` and `practices` as values built
once at boot — and `read` and `howTo` as *functions* that `readFileSync` on every call.

  PROSE — no restart at all. Measured:

    marker present before edit : 0
    (append RELOAD_PROBE_MARKER to curriculum/how-to/how-to-learn.md)
    marker present after edit  : 1   <-- no restart, no rebuild
    (revert)
    marker present after revert: 0

  MANIFESTS — boot-time. Measured on the same file the browser reads:

    progress.total before edit : 10
    (estimatedQuests: 10 -> 99 in curriculum/area-0/area.yml)
    progress.total after edit  : 10   <-- unchanged: needs the restart
    (revert)

  API SOURCE — the restart, and it is fast:

    (add devStackProbe: true to /health in apps/api/src/server.ts)
    $ ./infra/dev-stack.sh
    {"status":"ok","items":30,"devStackProbe":true}
    restart took 4 seconds (including the prebuild dist-parity check)

Both content edits were transient and reverted immediately; each file was verified
byte-identical afterwards by md5 and `git status --short curriculum/` was empty. Nothing
under `curriculum/` or `game/` is in this branch's diff — `git diff --stat HEAD --
curriculum/ game/` is empty.

So the honest instruction is the table in `infra/README.md`: writing prose, which is the
common case and the reason this plan exists, costs nothing at all. Only structure needs
the four seconds.
