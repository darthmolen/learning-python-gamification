Collections

Weeks 9–14 · 16 concepts · everything below is on the Boss 3 specification.

So far every variable has held exactly one thing. One number, one word, one answer. That runs out fast: a player has an inventory, a crafting table has a book of recipes, a world has a palette of blocks. This area is the four shapes Python gives you for holding many things at once, and the rule for choosing between them.

1 · Lists — things in order

A list holds items in the order you put them, and it can change after you make it. Square brackets, commas between.

# an inventory is a list inventory = ["stick", "coal", "stick", "wood"] inventory.append("flint") # add to the end inventory.remove("coal") # take the first one out len(inventory) # how many -> 4

Order is the whole point. "stick" appears twice and that is fine — a list does not care about duplicates.

2 · Indexing and slicing — reaching in

Indexing takes one item by position, counting from 0. Slicing takes a run of them, and the second number is where to stop, not the last one kept.

blocks = ["dirt", "stone", "coal", "iron", "gold"] blocks[0] # "dirt" — the first blocks[-1] # "gold" — the last blocks[1:3] # ["stone", "coal"] — stops before 3 blocks[1:-1] # everything but the ends
TRAP
blocks[5] on a five-item list raises IndexError. Five items means the last index is 4. Counting from zero costs you exactly one mistake, once, and then never again.

3 · Dicts — a key that finds a value

A dict is a lookup. You give it a key and it hands back the value you stored under that key. Unordered by intent — you do not ask a dict for its third thing, you ask it for the thing called "coal".

recipe = {"stick": 1, "coal": 1} recipe["coal"] # 1 recipe["gold"] # KeyError — there is no such key recipe.get("gold", 0) # 0 — a default instead of a crash for block in recipe: # walks the KEYS print(block, recipe[block])
TRAP — the one that will bite you
A missing key is not zero. If the inventory has never held coal, then inventory["coal"] does not answer 0 — it raises KeyError and stops your program. When you mean "however many, possibly none", say .get(key, 0).

4 · Sets — what is present, once

A set answers one question fast: is this in here? No order, no duplicates, no counting. A block palette is a set — a world either uses sandstone or it does not.

palette = {"dirt", "stone", "dirt"} # -> {"dirt", "stone"} "stone" in palette # True palette.add("glass") palette | other # in either palette & other # in both

6 · Nesting — collections inside collections

A recipe book is a dict whose values are themselves dicts. Nothing new is happening: you reach in one layer at a time, left to right.

RECIPES = { "torch": {"stick": 1, "coal": 1}, "chest": {"wood": 8}, } RECIPES["torch"] # {"stick": 1, "coal": 1} RECIPES["torch"]["coal"] # 1

7 · The five that work on all of them

len(x) # how many item in x # is it there — fast on a set, slow on a long list sorted(x) # a NEW list, in order; the original is untouched min(x), max(x)
